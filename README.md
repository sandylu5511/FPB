# 密匣 · MixiaVault

一个**纯本地**的 Android 加密笔记与照片库。没有账号、没有云端、没有同步服务器 ——
数据以密文形式存在应用私有目录，解锁密钥由本机主密码派生。

> 交接与运维信息见 **[HANDOFF.md](HANDOFF.md)**；本版发布细节见
> **[dist/FPB-v1.0.8-发布说明.md](dist/FPB-v1.0.8-发布说明.md)**。

---

## 一、定位与设计前提

「密匣」的出发点是：**个人备忘与私人照片不该离开这台手机。**

这带来一条贯穿全部设计的硬约束：

> **明文永不落盘。** 解密后的内容只存在于内存，用完即弃；连看一张实况照片的影片段，
> 也是内存里解密后直接喂给播放器，不写任何临时文件。

以及一条随之而来的取舍：

> **没有云端恢复。** 主密码与恢复码是唯一的找回途径；卸载应用会连同密钥文件一起抹掉，
> 数据将**永久无法解密**。因此发布签名密钥必须长期保持同一把（见 §六）。

## 二、功能

| 模块 | 能力 |
|---|---|
| 备忘录 | 标题 / 正文 / 标签 / 收藏 / 全文搜索 |
| 照片库 | 从系统相册导入；缩略图网格；**多选批量删除** |
| 实况照片 | **识别 Google Motion Photo / 三星动态照片**，图库与详情页显示「实况」角标，大图页可播放影片 |
| 列表管理 | 长按进入多选，支持全选与批量删除；照片被删光的空记录会自动回收 |
| 加密 | AES-GCM（平台实现）+ Argon2id（BouncyCastle）派生密钥；分槽设计支持主密码与恢复码 |
| 解锁 | 主密码 / 恢复码 / 生物识别（androidx BiometricPrompt，对国产 ROM 有兜底） |
| 引导 | 全新安装时生成恢复码并要求抄写确认；支持设置**假密码**（decoy） |
| 备份 | 加密备份导出与导入；周期性的备份催办提醒 |
| 隐私 | **默认禁止截屏**（`FLAG_SECURE`，可在设置里关）；启动图标可伪装成备忘录 / 计算器 |
| 外观 | 深色 / 浅色 / 跟随系统 |
| 自检 | 加密内核自检（`CryptoSelfTest`），可在设备上现场证明算法实现正确 |

## 三、技术栈

| 项 | 选型 |
|---|---|
| 语言 / UI | Kotlin 2.0.21 + Jetpack Compose（BOM 2024.12.01，Material 3） |
| 构建 | AGP 8.7.3 / Gradle（wrapper 随仓） / JDK 17 目标 |
| 版本目录 | `gradle/libs.versions.toml` |
| 存储 | 手写 SQLite（`SqliteRowStore`）+ 文件块存储（`FileBlobStore`）；**无 ORM** |
| 加密 | 平台 JCE 的 AES-GCM；BouncyCastle 的 Argon2id（**不注册全局 Provider**，避免与系统 Conscrypt 冲突） |
| 生物识别 | `androidx.biometric`（并显式把 `fragment` 提到 1.8.9，见 `libs.versions.toml` 里的注释） |
| 兼容 | `minSdk 26` / `targetSdk 35` / `compileSdk 35`，包名 `com.fpb.vault` |

**加密内核是纯 JVM 逻辑**（不碰 `android.*`），所以能在普通单元测试里直接跑生产代码 ——
这是选 BouncyCastle 纯 Java 实现而非 native 库的原因之一。

## 五、构建与验证

### 环境

- JDK：使用 Android Studio 自带的 JBR，**必须显式指定**（本机默认 JDK 25 会让 AGP 8.7.3 的 Lint 崩溃）
- SDK：`local.properties` 里写 `sdk.dir=...`（该文件不入库）

### 命令

```bash
export JAVA_HOME="C:/Program Files/Android/Android Studio/jbr"

./gradlew.bat :app:testDebugUnitTest     # 单元测试，216 项
./gradlew.bat :app:assembleDebug         # 日常验证用包
./gradlew.bat :app:assembleRelease       # 正式包（需要本地签名凭据，见 §六）
```

`assembleRelease` 在**读不到签名凭据**时不会注册签名配置，会产出
`app-release-unsigned.apk`（装不上）—— 这样在没有凭据的机器上仍能编译。

### 真机验收

```bash
python tools/v108-acceptance.py          # debug 包，22 项
python tools/v108-release-acceptance.py  # release 包，28 项，含 FLAG_SECURE 正反对照
```

验收脚本**不清应用数据**（`install -r` 覆盖安装），开局会先断言"旧记录确实在"，
不在就主动判为不可验并退出 —— 这样"升级不丢数据 / 老记录能被回收"才是真的被验过。

**为什么 debug 与 release 要各验一遍**：release 会跑 R8。本项目里
`BytesMediaSource extends MediaDataSource` 的 `readAt/getSize/close` 是
**由 `MediaPlayer` 的 native 侧按名字回调**的，字节码里看不到调用点 ——
所以 debug 包能播**推不出** release 包能播。已用 `-keep` 规则 + mapping.txt + dex 三重核实。

## 六、签名与发布（重要）

Android 用「包名 + 签名证书」判定应用身份。**换了签名就等于换了一个应用**，
系统会拒绝覆盖安装；而密匣没有云端恢复，用户只能卸载重装，**旧数据将永久无法解密**。

所以：

1. 发布签名凭据放在本地 `keys/` 目录，**刻意不入库**（`.gitignore` 排除整个目录）。
2. 该目录同时包含密钥库文件与**写着明文口令的说明文档** —— 本仓库是公开仓库，因此整目录排除。
3. **必须把 `keys/` 离线备份到至少两处**（U 盘 / 密码管理器附件 / 加密网盘）。
4. 不要"换台电脑重新生成一个" —— 那会断掉升级链。

当前签名方案：**v2 + v3 开启，v1 关闭**（`minSdk 26` 起 v1 已无意义，只多一份可被篡改的清单）。
签名配置在 `app/build.gradle.kts` 里**显式声明**，不依赖 AGP 默认值 ——
默认值会随 AGP 版本变化，而"哪几个方案被签了"是**无法事后补救**的。

> ⚠️ 仓库内**不含**任何密钥、口令或凭据。如果你在历史提交里看到类似内容，请立即告知。

## 七、安全模型（简要）

- 主密码经 **Argon2id** 派生，不落盘；磁盘上是密钥文件（KDF 参数 + 校验值 + 被包裹的数据密钥）。
- 记录与索引分别加密：索引与正文都不以明文出现在 SQLite 中。
- 图片等附件独立加密为文件块，密文尺寸 = 明文 + 12 B nonce + 16 B GCM tag。
- 解锁后的明文只存在于内存；锁定时清理缓存（含由明文派生的形态信息）。
- 默认禁止截屏；提供**假密码**引导路径。
- 加密内核带设备自检，可现场验证算法实现。

**能力边界（如实说明）**：本应用防的是"拿到手机或拿到文件的人"，不防已 root 且能
实时注入进程的攻击者，也不提供任何云端找回。

## 九、开发约定

- **注释写"为什么"，不写"是什么"。** 尤其是那些看起来可以简化、实际不能简化的判据
  （例：实况照片的 `Item:Length` 含 XMP 自身长度，因此要不动点迭代）。
- **新增/修改判据要留下"为什么不是另一种写法"** —— 这个项目里好几种缺陷的根因都是
  "判据看起来对、但一次都没成立过"。
- **验收要有一条不依赖文本解析的证据。** 否则"解析不到"会被误读成"没生效"。
- **单元测试优先覆盖纯逻辑**：加密内核、编解码、实况识别、空记录判定都是纯 JVM 代码。
- **平台行为必须真机验**：SQLite 事务、平台 Cipher、Activity 标志、`MediaPlayer` 回调。
